# 制作提示词

这份文件是助手生成提示词时使用的内部骨架，不是让用户在提供素材前填写的入口。正常流程是用户先给本次 SRT、视频以及可选素材，并说明文档内容和采用范围、图片内容和用途；助手读取后再生成针对本次视频的可复制提示词。

生成前实际读取 SRT、检查视频、读取文档选定内容并查看图片。先简述本次核心理解及素材采用范围，再给已填好的提示词：具体路径、主题、口播重点、制作区间、指定材料和建议视觉叙事均由助手填入。不要默认代入旧项目，不让用户再填写已提供的信息。非关键未知偏好写成明确建议；缺少必要输入时仅询问缺口，不能将空白模板称为本次制作提示词。仅当用户明确索取通用模板时才直接展示骨架。

只有提交文件和素材说明时，本轮停在提示词。用户随后提交这份提示词，或明确要求按它执行，才进入审阅包设计；明确要求跳过提示词直接设计时遵从。不要把“文件已齐全”误判为已经提交制作指令。

```text
请使用 $ai-sticker-glass-video，为本次片段制作「贴纸科普为主、玻璃点缀」的视频。

本次输入
- 原视频：[助手填入本次文件绝对路径及已核实规格]
- 对应 SRT：[助手填入本次文件绝对路径及时间范围]
- 本段核心：[助手依据本次 SRT 和视频总结观众需要理解的内容]
- 文档素材：[助手列明文件、用户说明的内容和指定采用的章节／事实；没有则省略]
- 图片／录屏素材：[助手列明文件、实际内容和用户指定用途；没有则省略]
- 产品名、官网、Brief 约束：[助手填入已提供或已核实信息；无则省略]
- 制作范围：[助手填入本次源视频起止时间、SRT 基准及偏移；不明确时先核对]
- 建议视觉叙事：[助手根据本段语义写出具体连续变化和对象关系]
- 画面方式：[助手填入用户指定方式，或根据原片提出的具体建议]
- 输出目录：[助手填入指定目录，或本次素材目录下的新版本目录]

先读取完整稿件，检查视频、原声与 SRT 的对应关系，并用一句话说明观众最需要理解什么。保留原口播声音、顺序和含义，按语义把它做成连续视觉故事，同一产品、设备或窗口跨镜头保持一致；关键动作跟随关键词和重音，给结果留出阅读时间。

采用浅色背景、真实产品图／界面、白边贴纸、短标签、手绘箭头和局部放大。贴纸承担产品识别、功能解释、状态表达或关系引导；玻璃与弥散渐变集中用于产品亮相和窗口层次。每个时刻一个视觉中心。

按上述用户说明采用文档内容与图片；不得擅自扩展文档采用范围或改变图片用途。你主动补齐必要的官方 Logo、产品图片和公开资料，优先使用本次实测素材和客户资料。缺少真实操作素材时用明确标注的功能示意；记录来源、使用状态和事实边界，不编造操作结果、数字或尾句结论。

默认不新增配音、音乐或音效；有原声就保留，没有音频就按 SRT 做无声插入画面。底部预留后期字幕区域，先检查原片烧录字幕，并说明每个区间的字幕处理方案。

本轮先交付完整静态审阅包：
1. storyboard.html：覆盖整段所有语义场景的视觉故事板，含时间、口播、实际布局和动作说明。
2. STORYBOARD.md：详细带时间码分镜与素材映射，含每镜主体、素材编号、构图、动作关键词、转场、衔接、声音／字幕处理和待核查项。
3. 素材来源表.md：逐项记录本地路径或来源链接、用途、镜头、真实素材／原创示意类别及可用状态。
4. 两三张有代表性的静态关键帧与对照图，展示贴纸主风格、玻璃点缀和关键关系。

等我明确确认这版审阅包后，再制作动态预览和最终视频。确认后持续完成检查与修复，从实际导出的 MP4 验证手机可读性、音画同步、遮挡、转场、声音与结尾衔接，交付 MP4、含素材的可编辑工程和更新后的素材来源表。保留上版便于对比。
```

## 后续确认和修改的表达

- 采用提示词并开始设计：“按这份制作提示词执行，先给完整故事板、详细分镜与素材映射、素材来源表。”
- 确认制作：“设计审阅 v1 符合预期，按这个版本生成视频。”
- 只修改设计：“先改故事板：S03 的产品辨识度不足，增加真实界面；其他镜头保持。改好后给我审阅。”
- 确认后微调：“S04 合盖动作比‘关了’晚，提前到原声关键词附近，保留现有方案。”

这些只是供用户选用的表述，不要求固定口令。确认后的小幅时机／排版修复沿用已有授权；实质变更再审阅受影响部分。
